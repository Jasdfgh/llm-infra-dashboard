FP4 + Disagg + WideEP Composability

技术根因链
不是单一 bug，而是多层问题叠加：

① FP8 格式差异 → AMD 使用 f8e4m3fnuz，fused MoE kernel 的 QuantKey 不支持 → 整条 fused activation-quantization path 被 disable（PR #39387）→ 走非 fused 慢路径

② MoRI-EP 通信开销 → FP4 GEMM 单节点可用（AITER 493 shapes, 5806 TFLOPS on MI355X）， 但跨节点 EP 通信时数据格式转换和 all-to-all 开销未被优化

③ Fork vs Upstream 差距 → AMD engineer 说 SGLang main 上 DPA 不能复现， 但 InferenceX benchmark 用的是 fork image → fix 在 main 但 fork 上没有

SemiAnalysis 建议："re-allocate engineering resources away from pet single node projects like ATOM towards fixing composability"

AMD 被告知需要聚焦：FP4 + 分布式推理的 composability，而不是单节点优化。

Stable (未在收窄) — 这不是一个可以通过单个 PR 修复的问题。需要系统性地解决： FP8 fnuz 格式的 fused kernel 支持、MoRI EP 通信效率、fork 到 upstream 的回合。 AMD 承认问题存在，SemiAnalysis 持续施压，但解决需要多个季度的工程投入。
Layer 2 · Serving Architecture
TRT-LLM Exclusive Performance / ATOM 被拒
NVIDIA TRT-LLM 比 vLLM/SGLang 快 35-50%；AMD ATOM 被 vLLM 社区拒绝进入主线
High Trajectory: Stable
宏观信号
TRT-LLM 全球生产环境服务 billions of tokens/hour（TogetherAI 等）。 H100 Llama 4 70B FP8: TRT-LLM 4,800 tok/s vs vLLM 3,400 tok/s — 同硬件 35-50% 差距。
B200 DeepSeek R1: TRT-LLM 达到 5,393 tok/s/GPU。
→ NVIDIA TRT-LLM Blog
AMD 应对 — ATOM RFC 被拒
AMD 提交 RFC #33478（2026-01-29）：将 ATOM 作为 vLLM model implementation backend。

vLLM lead maintainer @simon-mo 拒绝（2026-02-03）：
"The core value proposition of vLLM is that the SAME model implementation works across all hardware SKUs. I would not be against a vllm-atom plugin maintained out-of-tree. However, I am against putting this in-tree."

推荐路径：ATOM 作为 speed-of-light reference → 提取最优 kernels → upstream 到 vLLM

AMD @sunway513 接受（2026-02-05）："We will reframe the RFC to focus on plugin-oriented approach."
RFC 于 2026-02-06 正式关闭。
I
vLLM #33478 — ATOM RFC + community discussion
第三方评估
SemiAnalysis InferenceX v2：
"ATOM has zero customers in production... lacking tool parsing, wideEP, disagg, KV offloading. We would encourage AMD management to re-deploy these 10x engineers towards vLLM and SGLang."

vLLM maintainer @mgoin 质疑 ATOM benchmark（2026-02-03）： "Why is the speedup so small, just ~7%? The ATOM README claims 2-3x."
趋势判断
Stable (结构性差距) — AMD 无法通过独立引擎追平 TRT-LLM。 社区共识是 upstream kernel 到 vLLM/SGLang。这条路更慢但可持续。 只要 NVIDIA 继续投资 TRT-LLM，这个差距就会持续存在。
Layer 2 · Serving Architecture
vLLM Router MoRI Integration

High Trajectory: Closing ↑
